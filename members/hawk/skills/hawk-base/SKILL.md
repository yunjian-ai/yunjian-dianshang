# 货郎的底子

## 0. 先读
- 先读进度文件 `~/.yunjian/hawk/进度.md`（没有就照 hawk-base/进度模板.md 建；写的时候改对应那一块，不往末尾追加流水）：上回做到哪，有断点就接着做，不从头再问。
- `库/README.md`（文件夹、两种地图）；卡的格式和变更单六步同算盘一套（`库/模板/变更单.md`、`库/模板/决策卡.md`）。
- 本目录 `底子.py`（别的脚本都从这里读参数）、`指纹.py`（官方正文指纹）、`决策卡.py`（写经营决策卡）、`进度模板.md`（进度文件的样子）。

## 1. 每周巡检（定时，或主人说「查一下规则变没变」）
- 平台规则库每张卡：打开「官方链接」，取正文存成 `编号-正文.txt`（「----正文----」以下是正文），`python3 指纹.py <文件>` 和卡上「正文指纹」比。一样：「核对日期」改今天；不一样：写变更单（旧怎么写、新怎么写、影响哪些脚本和技能），附原文请主人看一眼，点头才换卡。
- 卡的「核对日期」超过 90 天：这周一定要重核。
- 自动化地图：只读路线（M-LP、M-DD-101、M-TB、M-PD）长时间没走的空走一遍，只看不点。

## 2. 路线走不通（自愈）
页面上找不到地图写的字：卡上「连续失败」+1、截图存证 → 照现在的页面重新找路 → **只读路线**试走一遍通了就换上，告诉主人一句；**会改东西的路线**（M-DD-102、M-BY-001 的改动部分）新路线先给主人看、点头才启用。旧版留着，「版本」+1。

## 3. 主人定的规矩（经营决策库）
主人说「以后不做 39 块以下的」「爆品线改成……」「这款转主推」：用本目录 `决策卡.py` 写（`--类 ZC|HP|DR --标题 … --原话 「主人原话」 --参数 名=值`），它自动取号、套 `库/模板/决策卡.md`、写生效日期；同标题已有生效的会拦，改就加 `--替代 <编号>`（旧卡自动改「已停用」不删）。不手写卡。售价下限这类写 `--参数 售价下限=39`，标签匹配会硬卡。卡里的参数名和 `库/默认值/选品上架-服装店.md` 的参数同名，脚本就会用主人的。

## 4. 干活撞上的变化
上架被驳回、后台多了新按钮、页面写的规则和卡不一样：都写变更单，照上面走；告诉主人一句「什么变了、影响什么、已经换好还是等您点头」。

## 5. 给主人看的呈现（杨先生 10-31）
数据类的结果一律数据化展示，**按主人看的界面出最好看的那种**：
| 界面 | 怎么出 |
|---|---|
| Grok Bot、手机聊天框（窄） | 脚本默认的窄表：≤5 列、每格尽量短；出处用 ①② 编号、完整出处列在表下；长理由放表下「说明」一条一条写。列多了就拆成两张表，不硬塞 |
| 电脑、飞书文档、网页（宽） | 加 `--宽` 出一张宽表 |
| 多维对比（款 × 平台 × 指标、几周走势） | 平台能出图或网页就出一张图／网页表，再附三五句要点；不能就拆成几张窄表 |
- 每张表上面先一句话说结论（几款过线、推荐哪款、要主人定什么）。
- 每个数都有出处：平台·页面或榜单·店铺·记录时间；主人说的写「主人说（日期）」；跨平台的尤其写全。
- 脚本出的表原样贴，不改成一段话；同一行不并两款（并了出处就丢）。

做完写进度：这次做到哪、下一步、等主人定的写回 `~/.yunjian/hawk/进度.md`，不靠聊天记录。
