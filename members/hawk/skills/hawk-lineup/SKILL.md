# 上新节奏和货盘

## 0. 先读
- 先读进度文件 `~/.yunjian/hawk/进度.md`（没有就照 hawk-base/进度模板.md 建；写的时候改对应那一块，不往末尾追加流水）：上回做到哪，有断点就接着做，不从头再问。
- 店铺标签卡；经营决策库里的货盘卡（D-HP）；`库/默认值/选品上架-服装店.md`（新品没动销提醒天数、平台自动下架天数）。
- 规则卡 R-SP-005（每天发品额度、草稿 15 天、无销量 30 天自动下架）；地图 M-DD-101（商机中心：应季爆发、降温爆发）。
- 本目录 `货盘.py`。

## 1. 货盘体检
抄一份在售款（商品、价格、上架日期、总销量；抖店商品管理能看到。**上架日期用「创建时间」**：列表上的「上架时间」重新上架、编辑后会刷新，拿它判新品不准——2026-10-31 实测），`python3 货盘.py <在售款.csv>`：
- 上架 ≥25 天还没卖出一件 → 提醒「再过约 N 天可能被平台自动下架」，请主人定：转主推、改链接还是放弃；
- 上架 7 天内的新品：看成交件数、推广达人数、退货率（推广达人数从联盟、退货率从算盘拿；拿不到写「没拿到」）。

## 2. 每款状态
状态只有四种：新品 → 主推 → 清仓 → 下架。货郎**提建议**（依据：新品 7 天表现、近 30 天销量、退货率、季节），**主人点头**才改；改了在这款的货盘卡下加一行历史，不删旧行。清仓、下架在后台的操作由主人点。

## 3. 上新日历
- 跟季节：商机中心「应季爆发」「降温爆发」，加上天气在往哪走（再过一周、一个月要厚的还是薄的），提前一到两周排下一季的款；
- 跟热度：hawk-scout 新过线的款；
- 每周上几款按主人定的；每天发品额度（R-SP-005）一般用不完，只在量大时提醒。
```
下周上新（日期）：
1. 加绒半拉链立领卫衣（选品卡 AQ-1108，过线，推荐直播）—— 降温在前，先上
2. …
货盘提醒：重磅美式卫衣 25 天 0 销量，约 5 天后可能被自动下架
```

## 4. 写回
货盘表、日历、主人定的状态改动写回进度；掌柜装了，货盘表就是掌柜「上新板」读的那一份。

给主人看的表照 hawk-base 第 5 节出（窄聊天框用默认窄表，电脑、飞书加 --宽；每个数带出处）。

做完写进度：这次做到哪、下一步、等主人定的写回 `~/.yunjian/hawk/进度.md`，不靠聊天记录。
